## 1. Базовые понятия RL

**Reinforcement Learning (RL)** - это обучение агента через взаимодействие со средой. Агент наблюдает состояние `s`, выбирает действие `a`, получает награду `r` и переходит в новое состояние `s'`. В отличие от supervised learning, здесь нет правильного ответа на каждом шаге: качество действий оценивается через полученные награды.

Часто задача задаётся как **MDP**:

```math
(S, A, P, R, \gamma)
```

где `S` - множество состояний, `A` - множество действий, `P(s'|s,a)` - динамика переходов, `R` - функция награды, `γ` - discount factor. Важное свойство MDP - **марковость**: следующее состояние и награда зависят только от текущих `s` и `a`, а не от всей истории.

**Политика** `π(a|s)` задаёт, как агент выбирает действия. Цель RL - найти политику, максимизирующую ожидаемую суммарную награду, то есть **return**:

```math
G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + ...
```

Если `γ` близко к 0, агент в основном думает о ближайшей награде. Если `γ` близко к 1, будущие награды становятся почти такими же важными, как текущие. Главные сложности RL: задержанные награды, случайность среды, большие пространства состояний и действий, а также баланс между exploration и exploitation.

## 2. Метод кросс-энтропии: табличный и нейросетевой

**Cross-Entropy Method (CEM)** - простой black-box метод поиска хорошей политики. Он не требует знания динамики среды: достаточно запускать эпизоды и считать итоговую награду.

Общий алгоритм:

```text
1. Инициализировать политику.
2. Сгенерировать много эпизодов.
3. Выбрать лучшие эпизоды - elite sessions.
4. Обновить политику так, чтобы действия из elite выбирались чаще.
5. Повторять.
```

В **табличном варианте** политика хранится как таблица вероятностей `π(a|s)`. Для каждого состояния записано распределение по действиям. После отбора elite-эпизодов вероятности обновляются по частотам: если в лучших траекториях в состоянии `s` часто выбирали действие `a`, то `π(a|s)` увеличивается.

В варианте с **нейронной сетью** политика задаётся как `πθ(a|s)`. Сеть принимает состояние и выдаёт вероятности действий. После генерации эпизодов берутся пары `(s, a)` из elite sessions: состояние становится входом, а действие - правильной меткой. Сеть обучается как классификатор через cross-entropy loss:

```math
L = -\log \pi_\theta(a|s)
```

Плюс CEM - простота. Минусы: нужно много полных эпизодов, метод плохо использует неэлитные траектории и может быть неэффективен в сложных задачах.

## 3. `V(s)` и `Q(s,a)`

`V(s)` и `Q(s,a)` - это функции ценности, которые помогают понять, насколько хороши состояния и действия.

**State-value function**:

```math
V^\pi(s) = \mathbb{E}_\pi[G_t \mid s_t=s]
```

Она показывает, какую ожидаемую суммарную награду получит агент, если окажется в состоянии `s` и дальше будет следовать политике `π`. То есть `V(s)` оценивает само состояние.

**Action-value function**:

```math
Q^\pi(s,a) = \mathbb{E}_\pi[G_t \mid s_t=s, a_t=a]
```

Она показывает, какую ожидаемую суммарную награду получит агент, если в состоянии `s` сначала сделает действие `a`, а потом будет следовать политике `π`. То есть `Q(s,a)` оценивает конкретное действие в конкретном состоянии.

Если известна оптимальная функция `Q*(s,a)`, то оптимальная политика выбирает действие с максимальным значением:

```math
\pi^*(s) = \arg\max_a Q^*(s,a)
```

А оптимальная ценность состояния:

```math
V^*(s) = \max_a Q^*(s,a)
```

## 4. Policy Iteration

**Policy Iteration** - метод поиска оптимальной политики в MDP. Он чередует два шага: оценку текущей политики и её улучшение.

Сначала берётся произвольная политика `π`. Затем выполняется **policy evaluation**: для текущей политики считается `Vπ(s)`, то есть ожидаемая награда из каждого состояния при следовании этой политике. Используется уравнение Беллмана:

```math
V^\pi(s) =
\sum_a \pi(a|s)
\sum_{s'} P(s'|s,a)
\left[
R(s,a,s') + \gamma V^\pi(s')
\right]
```

После этого выполняется **policy improvement**: политика становится жадной относительно найденных оценок:

```math
\pi_{new}(s) = \arg\max_a Q^\pi(s,a)
```

Затем процесс повторяется:

```text
Policy Evaluation → Policy Improvement → Policy Evaluation → ...
```

Когда политика перестаёт меняться, она считается оптимальной. Плюс Policy Iteration - обычно требуется мало итераций. Минус - каждая итерация дорогая, потому что нужно достаточно точно оценивать текущую политику.

## 5. Q-learning и SARSA

**Q-learning** и **SARSA** - model-free TD-методы. Они не знают модель среды `P(s'|s,a)`, а учатся по переходам:

```text
s_t, a_t, r_t, s_{t+1}
```

**Q-learning** обновляет `Q(s,a)` так:

```math
Q(s_t,a_t) \leftarrow Q(s_t,a_t) +
\alpha \left[
r_t + \gamma \max_{a'} Q(s_{t+1},a') - Q(s_t,a_t)
\right]
```

Он использует лучшее возможное действие в следующем состоянии. Поэтому Q-learning - **off-policy** метод: агент может исследовать среду одной политикой, например `ε-greedy`, но обучаться так, как будто дальше будет действовать жадно.

**SARSA** использует реально выбранное следующее действие:

```math
Q(s_t,a_t) \leftarrow Q(s_t,a_t) +
\alpha \left[
r_t + \gamma Q(s_{t+1},a_{t+1}) - Q(s_t,a_t)
\right]
```

Название SARSA означает последовательность: `State, Action, Reward, State, Action`. SARSA - **on-policy** метод: он учит именно ту политику, которой агент реально следует. Поэтому SARSA часто осторожнее, особенно если во время обучения есть случайные exploratory-действия.

## 6. Exploration vs Exploitation

**Exploration vs Exploitation** - ключевая проблема RL.

**Exploitation** - использовать лучшее известное действие:

```math
a = \arg\max_a Q(s,a)
```

Это даёт хорошую награду сейчас, но агент может застрять в неоптимальной стратегии.

**Exploration** - пробовать новые действия, чтобы найти потенциально лучшие варианты. Это может временно снижать награду, но помогает обучению.

Простой способ баланса - **ε-greedy**:

```text
с вероятностью ε выбрать случайное действие;
с вероятностью 1 - ε выбрать лучшее действие.
```

Например, при `ε = 0.1` агент 10% времени исследует, а 90% времени выбирает лучшее известное действие. Обычно `ε` постепенно уменьшают: сначала агент почти ничего не знает и должен много исследовать, а потом чаще использует найденную стратегию. Если exploration слишком мало, агент может не найти хорошую политику; если слишком много - он будет часто делать плохие действия.

## 7. DQN

**DQN (Deep Q-Network)** - это Q-learning, где таблица `Q(s,a)` заменяется нейронной сетью:

```math
Q(s,a) \approx Q_\theta(s,a)
```

Это нужно, когда состояний слишком много, например если состояние - изображение из игры. На вход сеть получает состояние `s`, а на выходе выдаёт Q-values для всех возможных действий:

```text
Q(s,a1), Q(s,a2), Q(s,a3), ...
```

Действие выбирается как:

```math
a = \arg\max_a Q_\theta(s,a)
```

Обучение похоже на обычный Q-learning. Target:

```math
y = r + \gamma \max_{a'} Q(s',a')
```

Loss:

```math
L = (Q_\theta(s,a) - y)^2
```

Проблема простого DQN - нестабильность: соседние состояния сильно коррелированы, target зависит от самой обучаемой сети, а изменение параметров может сразу поменять много Q-values. Поэтому в DQN используют experience replay и target network.

---

## 8. Experience Replay

**Experience Replay** - это буфер опыта, куда агент сохраняет переходы:

```text
(s, a, r, s', done)
```

Во время обучения из буфера случайно выбирается mini-batch переходов. Это лучше, чем учиться только на последних шагах подряд, потому что последовательные состояния часто очень похожи друг на друга.

Алгоритм:

```text
1. Агент взаимодействует со средой.
2. Переход сохраняется в replay buffer.
3. Из буфера случайно берётся batch.
4. Для batch считается target.
5. Сеть обновляется градиентным спуском.
```

Плюсы experience replay: он разрушает корреляции между соседними переходами, позволяет использовать один и тот же опыт несколько раз, повышает sample efficiency и стабилизирует обучение нейросети.

Минусы: нужен дополнительный объём памяти, а старый опыт может стать менее актуальным. DQN хорошо сочетается с replay buffer, потому что Q-learning является off-policy методом.

---

## 9. Target Network

**Target Network** - это отдельная замороженная копия Q-сети, которая используется для вычисления target.

В обычном DQN target зависит от той же сети, которую мы обучаем:

```math
y = r + \gamma \max_{a'} Q_\theta(s',a')
```

Из-за этого сеть гонится за постоянно меняющейся целью. Чтобы стабилизировать обучение, вводят две сети:

```text
online network: Q_θ
target network: Q_{θ-}
```

Online network обучается, а target network используется для расчёта target:

```math
y = r + \gamma \max_{a'} Q_{\theta^-}(s',a')
```

Периодически веса online network копируются в target network:

```text
каждые C шагов: θ- ← θ
```

Так target меняется медленнее, и обучение становится более стабильным.

---

## 10. Double DQN

**Double DQN** - модификация DQN, которая уменьшает завышение Q-values.

В обычном DQN операция `max` одновременно выбирает действие и оценивает его:

```math
y = r + \gamma \max_{a'} Q_{\theta^-}(s',a')
```

Если оценки шумные, максимум часто оказывается случайно завышенным. Это называется **overestimation bias**.

Double DQN разделяет выбор и оценку действия. Online network выбирает действие:

```math
a^* = \arg\max_{a'} Q_\theta(s',a')
```

А target network оценивает это действие:

```math
y = r + \gamma Q_{\theta^-}(s',a^*)
```

Или в одной формуле:

```math
y = r + \gamma Q_{\theta^-}(s', \arg\max_{a'} Q_\theta(s',a'))
```

Главная идея: не использовать одну и ту же оценку и для выбора, и для вычисления значения. Это делает Q-values менее завышенными и обучение более стабильным.

## 11. Policy Gradient

**Policy Gradient** - методы, которые напрямую обучают политику `πθ(a|s)`, а не только value-функцию. Цель - максимизировать ожидаемую награду:

```math
J(\theta) = \mathbb{E}[R]
```

Идея: если действие привело к высокой награде, нужно увеличить вероятность такого действия; если к низкой - уменьшить.

Общий вид градиента:

```math
\nabla J(\theta) =
\mathbb{E}
\left[
\nabla_\theta \log \pi_\theta(a|s) Q(s,a)
\right]
```

Здесь `∇ log πθ(a|s)` показывает, как изменить параметры, чтобы выбранное действие стало вероятнее, а `Q(s,a)` показывает, насколько это действие хорошее.

Плюс policy gradient - можно обучать стохастическую политику напрямую и работать с дискретными действиями. Минус - высокая дисперсия оценок градиента, поэтому обучение может быть шумным и нестабильным.

---

## 12. REINFORCE

**REINFORCE** - базовый Monte Carlo policy gradient алгоритм. Он запускает эпизод, получает return и обновляет политику так, чтобы действия из успешных эпизодов становились вероятнее.

Алгоритм:

```text
1. Сгенерировать эпизод текущей политикой.
2. Посчитать return.
3. Увеличить вероятность действий, которые привели к хорошему return.
4. Уменьшить вероятность действий из плохих эпизодов.
```

Формула обновления:

```math
\nabla J \approx G_t \nabla_\theta \log \pi_\theta(a_t|s_t)
```

Для генерации последовательностей можно записать:

```math
\nabla J \approx R(x,y) \nabla_\theta \log \pi_\theta(y|x)
```

Главный плюс REINFORCE - простота и общность. Он работает даже тогда, когда reward недифференцируемый. Главный минус - высокая дисперсия. Поэтому часто используют baseline, например `V(s)`, и обновляются по advantage:

```math
A(s,a) = G_t - V(s)
```

## 13. Actor-Critic

**Actor-Critic** объединяет policy-based и value-based подходы.

В нём есть две части:

```text
Actor  - выбирает действия, то есть задаёт πθ(a|s).
Critic - оценивает состояния или действия, например V(s) или Q(s,a).
```

Actor отвечает за поведение агента. Critic говорит, насколько выбранное действие было хорошим. Вместо полного Monte Carlo return Critic часто использует TD-оценку:

```math
A(s,a) \approx r + \gamma V(s') - V(s)
```

Это значение можно интерпретировать как advantage: действие лучше или хуже ожидаемого.

Actor обновляется так, чтобы чаще выбирать действия с положительным advantage и реже - с отрицательным. Critic отдельно обучается предсказывать `V(s)` или `Q(s,a)`.

Плюс Actor-Critic - обычно меньше дисперсия, чем у REINFORCE. Минус - нужно обучать две модели, и ошибки Critic могут мешать Actor.

## 14. Применение RNN для генерации последовательностей

**RNN** применяются для работы с последовательностями: текстом, речью, музыкой, временными рядами. Главная идея RNN - хранить скрытое состояние `h`, которое содержит информацию о предыдущих элементах.

В языковой модели задача - предсказывать следующий токен:

```math
P(text) = P(w_0)P(w_1|w_0)P(w_2|w_0,w_1)...
```

На каждом шаге RNN получает текущий токен и hidden state, обновляет hidden state и выдаёт распределение вероятностей следующего токена:

```math
P(x_{t+1}|x_0, ..., x_t)
```

При обучении обычно используется **teacher forcing**: модель получает правильные предыдущие токены и учится предсказывать следующий правильный токен. Loss:

```math
L = \sum_t -\log P(x_{t+1}|x_{0:t})
```

При генерации модель уже использует свои собственные предсказания: выбирает следующий токен, подаёт его себе на вход и продолжает. Токены можно выбирать greedy-способом, sampling-ом или beam search. Для длинных зависимостей вместо простой RNN часто используют LSTM или GRU.

## 15. Применение RL к дообучению моделей генерации последовательностей

В генерации последовательностей supervised learning не всегда оптимален. Например, в переводе, captioning или диалоге может быть много правильных ответов, а реальная метрика качества может быть недифференцируемой: BLEU, CIDEr, оценка пользователя или reward model.

RL позволяет дообучать генеративную модель напрямую под reward. Модель рассматривается как политика:

```math
\pi_\theta(y|x)
```

где `x` - вход, а `y` - сгенерированная последовательность. Действия - выбор токенов. Reward выдаётся за всю последовательность или за отдельные шаги.

Базовый вариант - REINFORCE:

```math
\nabla J \approx R(x,y) \nabla_\theta \log \pi_\theta(y|x)
```

Если сгенерированный ответ получил высокий reward, его вероятность увеличивается. Если reward низкий - уменьшается.

Также для такой задачи можно использовать **Self-Critical Sequence Training (SCST)**: в нём baseline берётся как reward greedy-ответа модели:

```math
A = R(sampled\ answer) - R(greedy\ answer)
```

Если sampled-ответ лучше greedy-ответа, его вероятность повышают; если хуже - понижают. Обычно сначала делают supervised pretraining, а потом RL fine-tuning, потому что обучение policy gradient с нуля слишком шумное.
